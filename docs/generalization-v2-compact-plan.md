# Compact mesh-field branch, declared before development

The [depth-12 feasibility checkpoint](generalization-v2/feasibility-checkpoint.md) supersedes the unrun deeper weighted-octree screen. This is a representation-family comparison, not an improvement claim for q8 interpolation. The existing fresh split, eligibility conventions and geometric gates remain unchanged.

`CompactMeshField` owns only a query object and one contiguous serialized buffer. Count the object, every vertex, triangle, BVH node, codec parameter, offset and padding byte. Original meshes/oracles, build permutations, normals and adjacency are not retained. Query scratch and robust-predicate temporaries are disclosed.

Five deterministic development representations are compact f64, compact f32, Q24, Q28 and lossless XOR32. Only Q24/Q28/XOR32 compete for selection; both controls remain in final comparisons. Quantization is once per shared vertex, and no geometry is simplified, repaired or removed. Source vertices are reordered in fixed 21-bit-per-axis Morton order with original vertex-index ties, for every codec. Triangle indices/winding update accordingly. XOR32 blocks have at most 32 vertices and choose raw versus compressed by exact serialized byte count, with raw winning ties. Compressed blocks store one base vertex, three residual widths and packed coordinate XOR residuals; reconstruction preserves binary64 bits exactly.

The common header is exactly 80 bytes: eight magic/version/codec/index-width bytes; three uint32 counts; three uint32 section offsets; six binary64 domain bounds. Vertex sections are 24V, 12V, 48+9V, 48+ceil(84V/8), or complete XOR directory/block bytes respectively. Indices are uint16 when V <= 65536, otherwise uint32. Each BVH node is 20 bytes: six outward uint16 bounds plus two uint32 metadata. Preorder internal nodes have their left child next and an explicit right index; leaves contain first triangle/count, with at most 16 triangles. Split at the deterministic largest centroid extent and median, with fixed axis and triangle-index ties. Bounds derive from decoded geometry and are independently containment checked.

Queries use decoded triangles only: conservative BVH nearest-distance pruning followed by binary64 square root; exact boundary classification; parity with filtered/exact predicates and a fixed generic-direction retry sequence on shared-edge/vertex/coplanar degeneracy. Exhaustion is numerical-unresolved. Measurement rays intersect decoded triangles directly, grouping shared events by exact topology/identity rather than proximity. Existing cubic rays remain for adaptive/grid fields. Every decoded mesh undergoes manifold, nondegeneracy, self-intersection, domain and component-topology validation before acceptance; lossy invalidity is representation failure. Both extracted oracle-qualified topology levels remain mandatory.

Development is three old qualified meshes by five representations, built once each, full 100,000 uniform/near distributions, all old probes/audits, complete corrected rays, boundary audit and unchanged topology gates. All thirteen caps are retained logically; below intrinsic actual bytes is storage-infeasible and at/above it the same field/outcome is reused. Select by jointly passing development-mesh count within 1 MiB; then sum actual bytes with 2 MiB selection-only penalty per noncrossing; then construction/query cost and fixed Q24/Q28/XOR32 order. The declared screen excludes bit-depth, block-size and BVH searches. If f64 fails where reference passes, fix the implementation. Comparisons retain unsuccessful candidates and report any failure to beat the strongest passing compact control.

Independent verification decodes the entire buffer, checks offsets/padding/index limits, BVH exact triangle coverage and conservative bounds, and verifies original bit-exact geometry/connectivity for f64/XOR32. It measures lossy displacement and brute-forces decoded-triangle distance/sign and ray events against the unchanged original oracle. Tests cover narrow wedges, slivers, nested components, shared edge/vertex/tangent/coplanar rays, exact boundaries, almost-equal nearest distances, packing tails/constant axes, XOR block modes, index-width boundary, malformed buffers and standalone queries after original source destruction. CGAL OFF remains usable; ON provides decoded-mesh validation.

Only one heavy worker runs, with 1,610,612,736-byte peak working-set guard. Phase timings separate source/validation, encoding/decoded validation, BVH/packing and query work; nine warm batches and fresh-process build costs are explicit. No oracle/setup, extraction or prior process warming is conflated with field query costs.

Before fresh fitting, freeze the selected codec, all implementations/evaluators/source/executables, input/reference hashes and settings. Fresh methods are all eight unchanged v1 methods, compact f64/f32 and the selected codec. Adaptive seeds are 340 through 344; deterministic grid/compact fields build once. All four fresh meshes, every logical cap, failures/unknown references and strongest compact/q8 envelopes remain in the final matrix. Censored comparisons receive no percentage saving.
